# CLAUDE.md — Инструкция для ИИ-агента по разработке сайта юридической компании «ПравСтратег»

## 1. О проекте

**Название проекта:**  
Юридическая компания «ПравСтратег» под руководством Ивана Новикова.

**Позиционирование:**  
Компания оказывает комплексные юридические услуги физическим и юридическим лицам.  
Основная идея — не формальное оказание отдельных услуг, а анализ ситуации, разработка оптимальной правовой стратегии и последовательное решение задачи клиента.

**Целевая аудитория:**  
- Частные клиенты (имущество, семья, наследство, недвижимость, земля, социальные права).  
- Бизнес (ИП, собственники, руководители, организации).

## 8. Онлайн-оплата

### Сценарий А. Фиксированные услуги

Перечень:  
- консультация;  
- консультация с изучением документов;  
- письменное заключение;  
- анализ договора;  
- анализ судебной перспективы;  
- подготовка документов.

Карточка: название, описание, стоимость, состав, кнопка «Оплатить».

### Сценарий Б. Индивидуальные услуги

Страница «Оплатить по договору / счету»:  
- ФИО или организация;  
- номер договора/счета/заказа;  
- email;  
- согласованная сумма;  
- комментарий.

**Важно:** не доверять сумме из браузера. Для индивидуальных платежей — серверная проверка или создание платежной ссылки компанией.  
Каждый платеж → внутренний ID заказа, привязанный к услуге/договору/счету.

## 9. Платежная архитектура

**Исследовать:**  
ЮKassa, Т-Банк / Т-Касса, СБП, другие актуальные российские решения.

**Критерии:**  
комиссия, СБП, карты, платежные ссылки, возвраты, API, webhooks, 54-ФЗ, касса, чеки, работа с физлицами/юрлицами, безопасность, документация.

**Приоритет:**  
1. СБП  
2. Карты  
3. Счет / перевод для организаций

**Архитектура:**  
- основной и резервный провайдер;  
- абстрактный payment service/interface;  
- данные карт не хранить;  
- безопасная страница/SDK провайдера;  
- подтверждения через webhook (сервер-сервер).

**Реализовать:**  
- проверку подписи webhook;  
- idempotency;  
- статусы: pending / paid / canceled / refunded;  
- журнал событий;  
- защиту от повторной оплаты;  
- возврат;  
- тестовый режим.

## 10. Юридическая корректность оплаты

Проверить перед запуском:  
- ГК РФ;  
- защита прав потребителей;  
- 54-ФЗ;  
- 152-ФЗ;  
- правила дистанционного оказания услуг;  
- требования к чеку;  
- правила провайдера;  
- налоговые требования.

Для стандартных услуг — возможен акцепт оферты оплатой.  
Для сложных дел — оплата только после согласования предмета, объема, стоимости и договора.

## 20. Правила работы

- Не писать весь сайт сразу.  
- Работать как технический руководитель.  

**Перед началом:**  
1. Анализ требований.  
2. Выявление неясностей.  
3. Предложение архитектуры.  
4. Roadmap.  
5. Декомпозиция на этапы.  
6. Структура каталогов.  
7. Подтверждение → только затем код.

**На каждом этапе:**  
1. Цель.  
2. Список файлов.  
3. Код.  
4. Команды для WSL Ubuntu.  
5. Lint, typecheck, tests, build.  
6. Проверка результата.  
7. Отчет о сделанном.  
8. Следующий шаг.

**Принципы:**  
- не переписывать работающее без нужды;  
- не менять десятки файлов без объяснения;  
- не использовать временные костыли;  
- при нескольких решениях — сравнить;  
- при необходимости — проверять официальную документацию.
