# Подключение внешних сервисов

Решение от 06.09.2026: уведомления о заявках приходят **в Telegram**, не на почту.
Туда же уходят документы, приложенные клиентом.

Все значения хранятся в файле `.env` в корне проекта. Он не коммитится
в репозиторий и остаётся только на вашей машине и на сервере.

```bash
cd ~/PravStrateg
cp .env.example .env      # если файла ещё нет
nano .env                 # выйти с сохранением: Ctrl+O, Enter, Ctrl+X
```

## 1. Telegram — основной канал

**Обязательно.** Без этого форма на сайте не принимает обращения.

### Состояние: настроено и работает

Бот **@pravstrateg_bot** создан, токен и список получателей прописаны
в `.env`. Уведомления приходят двум адресатам — руководителю и помощнику.

Проверено боевой отправкой заявки с документом: карточка и файл доставлены
обоим, ошибок нет.

Токен и идентификаторы чатов хранятся только в `.env` и в репозиторий
не попадают.

### Как добавить ещё одного получателя

1. Человек открывает https://t.me/pravstrateg_bot и нажимает **«Запустить»**
   (либо отправляет `/start`). Без этого Telegram не разрешит боту ему писать —
   настройки будут верные, а уведомления не придут. Самая частая причина сбоя.
2. Узнать его `chat_id` одним из способов:

```bash
# из API бота — покажет всех, кто с ним начинал диалог
curl -s "https://api.telegram.org/bot<ТОКЕН>/getUpdates" | grep -o '"id":[0-9]*'
```

   либо человек пишет боту **@userinfobot**, тот отвечает строкой `Id: …`.

3. Число дописывается в `TELEGRAM_CHAT_ID` через запятую. Количество
   получателей не ограничено, уведомление приходит каждому.

После правки `.env` нужен перезапуск: локально — перезапустить `npm run dev`,
на сервере — `docker compose restart`.

### Альтернатива: общий чат

Вместо перечисления людей можно создать групповой чат, добавить туда
@pravstrateg_bot и Ивана, и указать `chat_id` группы (он отрицательный,
вида `-1001234567890`). Так удобнее, когда в компании появятся другие
юристы: достаточно добавить человека в чат, `.env` править не нужно.

### Что приходит в Telegram

Карточка обращения со всем необходимым, чтобы сразу выйти на клиента:

```
Заявка № 0609-4F2A
Анализ документов · Наследственные дела
Физическое лицо

Пётр Смирнов
+7 905 111 22 33          ← нажатие звонит
petr.smirnov@example.com  ← нажатие открывает почту
@petr_smirnov

Ситуация
Отец умер в марте, я единственный сын...

📎 Документов: 1 — приходят следующими сообщениями

Принято 06.09.2026, 18:40 (Калининград)
Согласие на обработку ПД получено, редакция 04.09.2026

[ Написать в Telegram ]  [ Написать в WhatsApp ]
```

- **Номер заявки** — короткий, его удобно назвать клиенту вслух и найти
  поиском в переписке с ботом, когда дело уже в работе.
- **Телефон и почта** Telegram делает нажимаемыми сам.
- **Кнопки** появляются автоматически: Telegram — если клиент оставил ник,
  WhatsApp — по номеру телефона.
- **Документы** приходят следующими сообщениями с подписью и номером заявки.
- Длинное описание разбивается на части, ничего не обрезается.

## 2. Почта — не используется

Почта как канал уведомлений убрана полностью: из `.env`, из зависимостей проекта
и из кода. Пароль для внешних приложений Mail.ru не нужен.

**Следствие, о котором стоит знать:** резервного канала нет. Если Telegram окажется
недоступен, заявка не уйдёт никуда — клиент увидит сообщение с просьбой позвонить
и номер телефона. Обращение не пропадает молча, но и не доходит само.

Практически это редкий сценарий: сбои Telegram недолгие, а перед отправкой
выполняется повторная попытка. Но если однажды захочется подстраховаться,
вариантов два — вернуть отправку письмом или добавить второго получателя
в другом мессенджере.

## 3. Яндекс.Метрика — статистика

**Не обязательно.** Можно подключить в любой момент, в том числе после запуска.

### Под каким аккаунтом

Любой аккаунт Яндекса, но лучше завести **отдельный рабочий**, а не использовать
личный: доступ к Метрике со временем придётся давать подрядчикам по продвижению.
Тот же аккаунт пригодится для Яндекс.Вебмастера.

### Состояние: настроено

Счётчик **112331994** создан и прописан в `.env`.

```
NEXT_PUBLIC_YANDEX_METRIKA_ID=112331994
```

Номер счётчика не секрет — он виден в исходном коде любой страницы сайта.

Параметры при создании выбраны так:

| Параметр | Значение | Почему |
|---|---|---|
| Часовой пояс | GMT+02:00 Калининград | Место работы оператора; совпадает со временем в уведомлениях Telegram |
| Включая поддомены | Да | Иначе заходы по `www.` могут не попасть в статистику |
| Вебвизор, аналитика форм | **Выключено** | Записывает содержимое полей — на форме люди описывают наследственные, семейные и военные дела. В коде счётчика также стоит `webvisor: false` |

Код счётчика с сайта Метрики вставлять никуда не нужно — он уже встроен
в компонент `src/components/analytics/CookieConsent.tsx`.

### Что осталось

- Проверка установки в интерфейсе Метрики пройдёт только после развёртывания
  на сервере: сейчас сайт снаружи недоступен.
- После запуска настроить цели: отправка формы, клик по телефону.
- Дать доступ к счётчику Яндекс-аккаунту Ивана (настройки счётчика → «Доступ»),
  чтобы статистика не была привязана к одному человеку.

### Особенность

Счётчик загружается **только после нажатия «Принять»** в баннере cookie —
этого требует пункт 9.2.2 политики обработки персональных данных. Посетители,
отказавшиеся от cookie, в статистику не попадут, цифры будут ниже реальных.
