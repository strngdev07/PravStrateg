# Подключение внешних сервисов

Три подключения, которые делает Иван лично. Все значения попадают в файл `.env`
в корне проекта — он не коммитится в репозиторий и никуда не отправляется.

**Присылать пароли в переписке не нужно.** Вы вписываете значения в `.env` сами,
по образцу ниже. Я эти значения не вижу, и они не нужны мне для работы.

Подготовка (один раз):

```bash
cd ~/PravStrateg
cp .env.example .env
nano .env          # выйти с сохранением: Ctrl+O, Enter, Ctrl+X
```

## 1. Почта — приём заявок с сайта

**Обязательно.** Без этого форма на сайте не принимает обращения.

### Под каким аккаунтом

**`pravstrateg@mail.ru`** — тот ящик, куда должны приходить заявки.
Не `novikov_ivan1@mail.ru`: это другой аккаунт, он к сайту отношения не имеет.

### Зачем нужен отдельный пароль

Сайт отправляет письмо сам, как почтовая программа, — значит должен
авторизоваться на почтовом сервере. Обычный пароль от ящика Mail.ru от сторонних
программ не принимает. Пароль для внешнего приложения даёт право только на
отправку почты, отзывается одной кнопкой и не открывает доступ к переписке —
даже если файл с настройками попадёт не в те руки.

### Шаги

1. Открыть `mail.ru` на компьютере и войти под `pravstrateg@mail.ru`.
2. Правый верхний угол → **«Настройки»** → **«Все настройки»**.
3. Раздел **«Безопасность»** → **«Пароли для внешних приложений»**.
4. Нажать **«Добавить»**.
5. Название — любое понятное, например `Сайт pravstrateg`.
6. Если спросят протокол или область доступа — выбрать **SMTP (отправка почты)**.
7. Mail.ru покажет пароль. **Он показывается один раз** — скопировать сразу.

### Куда вписать

В `.env`, в строку `SMTP_PASSWORD`. Остальные строки уже заполнены правильно:

```
SMTP_HOST=smtp.mail.ru
SMTP_PORT=465
SMTP_USER=pravstrateg@mail.ru
SMTP_PASSWORD=сюда вставить скопированный пароль
MAIL_TO=pravstrateg@mail.ru
MAIL_FROM=pravstrateg@mail.ru
```

Пароль вставлять без кавычек и без пробелов по краям.

### Без этого

Форма отвечает «Форма временно недоступна, позвоните нам» и показывает телефон.
Обращения не теряются молча, но и не приходят. Остальной сайт работает полностью.

## 2. Telegram — дублирующее уведомление

**Не обязательно.** Заявки приходят на почту и без этого. Telegram нужен, чтобы
уведомление падало в телефон сразу, а не когда откроете почту.

### Под каким аккаунтом

Личный Telegram Ивана — тот, в который должны приходить уведомления.

### Шаги

1. В Telegram найти **@BotFather** и открыть чат.
2. Отправить `/newbot`.
3. Ввести отображаемое имя бота, например `ПравСтратег — заявки`.
4. Ввести адрес бота: латиницей, обязательно заканчивается на `bot`,
   например `pravstrateg_leads_bot`.
5. BotFather пришлёт **токен** — длинная строка вида `1234567890:AAH...`.
6. Найти **@userinfobot**, отправить ему любое сообщение — он ответит вашим `Id`.
   Это число и есть `chat_id`.
7. **Открыть чат со своим новым ботом и нажать «Запустить» (`/start`).**
   Без этого шага бот не имеет права вам писать, и уведомления не придут.
   Это самая частая причина, почему «всё настроил, а ничего не приходит».

### Куда вписать

```
TELEGRAM_BOT_TOKEN=токен от BotFather
TELEGRAM_CHAT_ID=число от userinfobot
```

### Без этого

Заявки приходят только на почту. Ничего не ломается.

Учтите: документы клиента уходят вложением **в письмо**. В Telegram приходит текст
обращения и отметка, сколько файлов приложено.

## 3. Яндекс.Метрика — статистика посещений

**Не обязательно.** Можно подключить в любой момент, в том числе через месяц
после запуска.

### Под каким аккаунтом

Любой аккаунт Яндекса. Рекомендую завести **отдельный рабочий**, а не использовать
личный: доступ к Метрике со временем придётся давать подрядчикам по продвижению,
и отдавать личную почту вместе со всем, что к ней привязано, не стоит.

Тот же аккаунт потом пригодится для Яндекс.Вебмастера.

### Зачем

Метрика показывает, сколько человек заходит, откуда пришли, какие страницы
смотрят, с телефона или компьютера, и сколько дошло до формы. Без неё нельзя
понять, работает сайт или нет. Пример: если на «Наследственные дела» приходит
половина трафика, а форму никто не отправляет — переписывать надо конкретно эту
страницу, а не сайт целиком. Без статистики это не видно.

### Шаги

1. Открыть `metrika.yandex.ru`, войти под рабочим аккаунтом.
2. Нажать **«Добавить счётчик»**.
3. Имя счётчика — `ПравСтратег`.
4. Домен сайта — `pravstrateg.ru`.
5. Принять условия, нажать **«Создать счётчик»**.
6. Номер счётчика — восьмизначное число вверху страницы счётчика.
   Код вставлять на сайт не нужно, он уже встроен.

### Куда вписать

```
NEXT_PUBLIC_YANDEX_METRIKA_ID=номер счётчика
```

Это единственное значение из трёх, которое не является секретом: номер счётчика
виден в исходном коде любой страницы сайта.

### Важная особенность

Счётчик загружается **только после того, как посетитель нажал «Принять»** в баннере
cookie. Это прямое требование пункта 9.2.2 вашей политики обработки персональных
данных. Юридически так правильно, но означает, что посетители, отказавшиеся от
cookie, в статистику не попадут — цифры будут ниже реальных. Это нормально и
ожидаемо.

### Без этого

Работает всё. Просто нет статистики.

## Применить настройки

После заполнения `.env`:

```bash
cd ~/PravStrateg
npm run dev
```

Открыть `http://localhost:3000/kontakty`, отправить тестовое обращение и приложить
любой PDF. Должно прийти письмо на `pravstrateg@mail.ru` с вложением и, если
настроен Telegram, уведомление в мессенджер.

На боевом сервере после правки `.env` нужен перезапуск:

```bash
sudo systemctl restart pravstrateg
```

## Сводка

| Подключение | Обязательно | Что не работает без него |
|---|---|---|
| Почта (`SMTP_PASSWORD`) | **Да** | Приём заявок с сайта |
| Telegram (токен и chat_id) | Нет | Мгновенные уведомления в телефон |
| Метрика (номер счётчика) | Нет | Статистика посещений |

Обязательное только одно — пароль почты. Это единственная функция, которая
приносит клиентов.
